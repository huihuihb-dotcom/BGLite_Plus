# BGLite_Plus 项目基准文档 (BASELINE.md)

## 1. 项目简介与设计哲学
- **项目名称**: BGLite_Plus (BiaoGe Plus - 魔兽世界怀旧服/时光服金团表格及辅助工具增强插件)
- **支持版本**: 经典旧世 (Vanilla / SoD)、燃烧的远征 (TBC)、巫妖王之怒 (WLK)、泰坦时光服 (Titan)、大地的裂变 (CTM)、熊猫人之谜 (MOP)。（注：正式服 Retail 不支持）
- **核心开发原则**:
  1. **外部依赖零侵入**: 对上游 `BGLite` 核心代码保持绝对只读，不修改上游源文件。所有增强与修复均通过安全 Hook、运行时修补、独立外挂模块或防御性代理实现。
  2. **全面沙箱与防御性容错**: 跨模块调用、暴雪原生异步 API 及外部插件数据交互必须全面覆盖 `pcall` 沙箱，提供安全回退兜底，严禁因单点异常掐死外层主执行栈。

> [!CAUTION]
> ### 🚨 核心功能安全红线与强制人工测试规范 (铁律)
> **凡是修改了以下 4 类底层关键位置的代码，AI 必须在回复的最上方以最显眼的警示框主动提醒用户进行游戏内真实开团人工闭环测试，绝不允许未经实测直接打包上线！**
> 1. **全局底层 API 拦截与包装**：如 `Core/Lib.lua` 中对 `BG.OnItemLoad`、`ContinueOnItemLoad`、`Item:CreateFrom...` 的拦截与包装；
> 2. **拍卖核心发起与出价链路**：如 `StartAuction`、`SendStartAuctionMsg`、`AuctionWAEvent.lua` 消息解码、出价倒计时；
> 3. **掉落拾取与对账系统**：如 `AutoAuctionOnLoot.lua`、`CHAT_MSG_LOOT` 监听、表格槽位匹配；
> 4. **交易与财务结算系统**：如自动交金、交易历史、欠款计算。

> **人工测试标准**：必须在游戏里组建一个 2 人以上团队，真实点开一件装备，完成**【弹出拍卖小框 -> 点击开始拍卖 -> 团队警告通报发出 -> 全团弹出拍卖出价条】**全流程闭环！

## 3. 核心业务机制与重大技术决策 (避坑指南)

### 3.1 掉落自动拍卖与预设起拍价 (AutoAuctionOnLoot / AuctionPreset)
1. **严格底价与高价值物资安全防线**:
   - `priceNum <= 0` 绝不自动开拍；橙装（quality == 5）、图纸与升级材料（任务道具 `bindType == 4`）默认不自动开拍；
   - 补充 `itemInfoCache` 与超链接色值判断（`link:find("|cffff8000")`），杜绝因 `GetItemInfo` 异步尚未缓存导致的橙装误判。
2. **槽位锁定假死根除**:
   - 槽位锁 `BiaoGe.autoAuctionedSlots` 采用服务端时间戳存储，陈旧锁（> 2小时）自动过期；
   - 注册 `ENCOUNTER_START` 与 `PLAYER_ENTERING_WORLD` 自动清空槽位锁，消除跨周或团灭假死。
3. **多阶梯异步对账与防抖**:
   - 首期查表延迟 0.20s，扩展 4 级重试阶梯（`0.20s -> 0.45s -> 0.85s -> 1.50s`），消除高频连续摸尸体掉落脱节；防抖合并时间放宽至 1.8s。
4. **官方掉落运行时增量修补 (零侵入)**:
   - 针对官方掉落库（`DB_Loot_Titan.lua`）遗漏 ZA 核心装备 `33291`（巫毒纹路腰带）与斩杀图纸 `33307`，在 `Core/DB/DB_Loot_SWtitan.lua` 独立模块中通过 `SafeAppend` 动态注入，保证预设面板正常渲染且不怕官方版本覆盖。
5. **副本白名单与 ObjectAPI 避坑**:
   - 校验待查副本有效性（`BG.Maxb[FB] > 0`），杜绝旧本（如 `"RS"`）导致算术异常；
   - 怀旧服原生 `ItemMixin` **不存在 `GetItemKey` 方法**，入口严格校验合法数字 ID 与 `item:(%d+)`，已缓存直接回调放行，未缓存安全挂载 `ContinueOnItemLoad`。
6. **改价关联副本强同步与输入框绝对优先权 (彻底解决改价不生效)**:
   - 封装 `SetPresetItemPrice` 等函数，单件改价与批量改价强制同时同步当前副本与关联别名副本（如 `SSC` 与 `SSCtitan`）的双类型键（数字键+字符串键）；
   - 拦截 `f.bt:SetScript("OnClick")` 与输入框 `OnTextChanged`，在开始拍卖前强制以输入框眼前的视觉真实文本覆写 `btn.money = manualMoney`，彻底粉碎 `f.bt.money` 历史脏数据死锁。

### 3.2 团队工具与防封通信 (RaidTool / TeamInfo / ItemOutTime)
1. **进组通知权限防御**: 开启 `notifyOnlyLeader`（仅团长/助理），在发送前校验 `UnitIsGroupLeader` 与 `UnitIsGroupAssistant`，杜绝误扰他人团队。
2. **语音超链接防第三方破坏屏障**:
   - 针对第三方粗暴正则破坏超链接的问题，采用中性安全协议 `garrmission:BGVoice_<TAG>_<NUM>`；
   - 文本采用管道颜色打断设计 `[%s|r|cff00BFFF %s]`（如 `[DD|r|cff00BFFF 123456]`），物理打断任意外部插件的粗暴正则，100% 免疫污染。
3. **合规表述与多平台识别**: 全面使用“语音频道”中性表述；全面兼容 DD、滴滴、KOOK、VX、集结号 MHH 协议，维护 100 行 FIFO 通报缓存池。
4. **装备过期时间抽屉与团队信息右侧互斥联动**:
   - 专用隐藏扫描 Tooltip 解析背包团本装备 `BIND_TRADE_TIME_REMAINING`，支持品质着色与彩色倒计时条；
   - 挂载双向 `OnShow` 钩子，主界面右侧永远只有单一抽屉展开，彻底杜绝【团队信息】与【装备过期】抽屉重叠打架。

1. **数据清洗与栏位收纳**: 彻底剔除节日副本（holiday）幽灵 CD 缓存；装备栏多材料/徽章采用 `+N` 悬停动态浮层展开收纳。

3. **战斗中稳定查看与闪烁消除**: 悬浮窗属于非受保护 Frame，战斗中完全支持正常查看；移除 Watchdog 中粗暴的 `InCombatLockdown` 强制隐藏，仅保留离开锚点 0.25s 缓冲平滑收起，消除高频振荡死循环。

### 3.5 团队专精嗅探与减伤监控 (RaidTalents / RaidComp / RaidCD)
1. **超视距专精嗅探中枢**: 跨模块集中解析全团专精与天赋，解决大团远距离队友未知问题；专精贴图严格对齐官方经典材质（如防骑 `spell_holy_devotionaura`），杜绝白板。

   - 用户关闭技能监控时，立即物理注销 `COMBAT_LOG_EVENT_UNFILTERED` 监听并清空活跃表，实现 0 CPU/内存常驻占用；按需重新开启时无缝恢复。

### 3.6 战术站位图体系 (RaidTacticalMap / RaidMap)
1. **全分辨率几何等比投影**: 标点坐标基于虚拟基准画布（`748 × 452`）等比映射，Boss 永远居中，全分辨率严丝合缝；9 张 1024x1024 高清实景底图调色板优化，体积骤降 76.6%（2.77MB）。

3. **打开即带入与职责元数据驱动**: 彻底改变手动点击同步交互，打开界面或切换首领时自动静默触发 `AutoAssignRosterToMap(true)` 智能落座；支持坦克/治疗溢出自动顺延填补，近战全员聚合于 `[98]` 集合组。

5. **三态运行架构与权限隔离**:
   - `EDITOR`（团长设计器）：全功能开放，支持同步、画板、全团广播与通报；

   - 通信协议永远只传输无缩放基准坐标（`baseX / baseY`），彻底根除因两端窗口分辨率不同导致的二次缩放膨胀错位；
   - 过滤自身广播反噬，重构基于位置的字符串精确切分，消除字段错位导致的人员空白。

   - **彻底剥离 SecureActionButton 根治战斗死锁**: 血条重构为原生非受保护 `Button`，彻底杜绝战斗中 `ADDON_ACTION_BLOCKED` 导致血条消失或无法拖动，实现战斗中 100% 自由显隐与任意拖拽；

   - **0 内存 GC 优化**: 预生成静态 `RAID_TARGET_UNITS` / `PARTY_TARGET_UNITS` 扫描数组并辅以 0.35s 节流，消除每秒 200+ 临时字符串与表分配；
   - **战斗生命周期防御**: 开怪自动截断退出主城 `/star test` 测试沙盘；移除不稳定 `PLAYER_REGEN_ENABLED`，生命周期严格对齐 `ENCOUNTER_END`；完善跨版本 Aura 解包与 8 色标记映射。
