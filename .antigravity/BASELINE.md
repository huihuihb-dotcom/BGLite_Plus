# BGLite_Plus 项目基准文档 (BASELINE.md)

## 1. 项目简介与设计哲学
- **项目名称**: BGLite_Plus (BiaoGe Plus - 魔兽世界怀旧服/时光服金团表格及辅助工具增强插件)
- **支持版本**: 经典旧世 (Vanilla / SoD)、燃烧的远征 (TBC)、巫妖王之怒 (WLK)、泰坦时光服 (Titan)、大地的裂变 (CTM)、熊猫人之谜 (MOP)。（注：正式服 Retail 不支持）
- **核心开发原则**:
  1. **外部依赖零侵入**: 对上游 `BGLite` 核心代码保持绝对只读，不修改上游源文件。所有增强与修复均通过安全 Hook、运行时修补、独立外挂模块或防御性代理实现。
  2. **全面沙箱与防御性容错**: 跨模块调用、暴雪原生异步 API 及外部插件数据交互必须全面覆盖 `pcall` 沙箱，提供安全回退兜底，严禁因单点异常掐死外层主执行栈。

> [!CAUTION]
> ### 🚨 核心功能安全红线与强制人工测试规范 (铁律)
> **凡是修改了以下 4 类底层关键位置的代码，AI 必须在回复的最上方以最显眼的警示框主动提醒用户进行游戏内真实开团人工闭环测试，绝不允许未经实测直接打包上线！**
> 1. **全局底层 API 拦截与包装**：如 `Core/Lib.lua` 中对 `BG.OnItemLoad`、`ContinueOnItemLoad`、`Item:CreateFrom...` 的拦截与包装；
> 2. **拍卖核心发起与出价链路**：如 `StartAuction`、`SendStartAuctionMsg`、`AuctionWAEvent.lua` 消息解码、出价倒计时；
> 3. **掉落拾取与对账系统**：如 `AutoAuctionOnLoot.lua`、`CHAT_MSG_LOOT` 监听、表格槽位匹配；
> 4. **交易与财务结算系统**：如自动交金、交易历史、欠款计算。
> 
> **人工测试标准**：必须在游戏里组建一个 2 人以上团队，真实点开一件装备，完成**【弹出拍卖小框 -> 点击开始拍卖 -> 团队警告通报发出 -> 全团弹出拍卖出价条】**全流程闭环！

## 3. 核心业务机制与重大技术决策 (避坑指南)

### 3.1 掉落自动拍卖与预设起拍价 (AutoAuctionOnLoot / AuctionPreset)
1. **严格底价安全防线**:
   - `priceNum <= 0` 绝不自动开拍，保留人工处理的底层防线；
   - 橙装（quality == 5）、图纸与升级材料（任务道具 `bindType == 4`）默认不自动开拍，防止团长高价值物资误拍。
2. **槽位锁定假死根除**:
   - 槽位锁 `BiaoGe.autoAuctionedSlots` 采用服务端时间戳存储，陈旧锁（> 2小时）自动过期；
   - 注册 `ENCOUNTER_START` 事件：Boss 开打瞬间自动清空该 Boss 全部槽位锁；进出副本（`PLAYER_ENTERING_WORLD`）自动清理，消除跨周假死。
3. **多阶梯异步对账与防抖**:
   - 针对 BGLite 写入表格的 0.10s 延迟，首期查表延迟设为 0.20s，并扩展 4 级重试阶梯（`0.20s -> 0.45s -> 0.85s -> 1.50s`），消除高频连续摸尸体掉落脱节；防抖合并时间放宽至 1.8s。
4. **副本白名单与跨版本脏数据拦截**:
   - 待查副本必须满足 `BG.Maxb[FB] and type(BG.Maxb[FB]) == "number" and BG.Maxb[FB] > 0`，杜绝时光服环境下因历史旧本（如 `"RS"`）导致 `nil + 1` 算术异常，切断执行栈；全量对账调用均加 `pcall` 保护。
5. **暴雪原生 ObjectAPI 异步加载避坑 (铁律)**:
   - **坑点**: 经典怀旧服客户端原生 `ItemMixin` 中**不存在公开的 `GetItemKey` 方法**，盲目判断 `GetItemKey` 会导致所有装备在入口被拦截，产生“全团拍卖静默无响应、无通报、无弹窗且无报错”的致命 Bug；
   - **防线**: 在 `Lib.lua` 中严格校验输入（仅接受数字 ID > 25 或含合法 `item:(%d+)` 的字符串），阻断普通备注或占位符进入；本地已缓存（`IsItemDataCached`）直接毫秒级放行回调；未缓存调用原生异步并挂载 `pcall` 兜底。
6. **TOC 双阵营掉落池合并**:
   - 十字军试炼 Boss 11~16 底层严格区分联盟/部落两套 ID，在 `CollectFBItems` 中通过 `TOC_FACTION_LOOT_TABLES` 自动合并双阵营掉落，确保无论团长当前登录何种阵营，预设底价均能覆盖两端，杜绝换号漏拍。

### 3.2 团队工具与防封语音通信 (RaidTool / TeamInfo)
1. **进组通知权限防御**:
   - 增加【仅团长/助理】（`notifyOnlyLeader`，默认开启），在 `CHAT_MSG_SYSTEM` 触发与延迟发送前校验 `UnitIsGroupLeader("player")` 与 `UnitIsGroupAssistant("player")`，杜绝玩家进入他人团队时误发密语或团队通知。
2. **语音超链接防第三方破坏屏障**:
   - **坑点**: 第三方插件（或原版 BiaoGe `YY.lua`）使用粗暴正则 `[yY]+%s*(%d+)` 二次扫描聊天消息，会将超链接切断破坏为 `BGLiteCop[YY:...]` 乱码；
   - **解决方案**:
     - 采用中性安全协议前缀 `garrmission:BGVoice_<TAG>_<NUM>`；
     - 文本渲染采用管道颜色打断设计 `[%s|r|cff00BFFF %s]`（如 `[DD|r|cff00BFFF 123456]`），原生渲染连贯，但物理打断了任意外部插件的粗暴正则，**100% 免疫第三方插件污染**。
3. **合规防封与多语音平台识别**:
   - 全面剔除游戏内视觉与聊天频道的“YY”敏感词，统一替换为合规中性表述“语音频道”；
   - 特征库与正则全面适配 `DD`、`dd`、`进DD`、`上DD`、`滴滴`、`KOOK`、`VX` 等，支持集结号 MHH 协议原生解码；
   - 团队信息通告池每个副本与组队状态保留 100 行时序通告，先进先出自动淘汰。
4. **抽屉式侧边栏架构与联合存储**:
   - 挂载在主框架右侧边缘（宽 340，高 480，层级 `GetFrameLevel() + 35`），切换任意 Tab 保持常驻；
   - 具备未绑定、已绑定、只读历史存档三态展示；在 `BG.SaveBiaoGe(FB)` 时将 `teamInfo` 深度拷贝进历史快照，实现历史账单与当时团队通告的联合自愈还原。

### 3.3 角色总览与数据资产 (RoleOverview / Reputation)
1. **节日副本 (holiday) CD 彻底剔除与自愈**:
   - 重构 CD 逻辑，识别并清洗历史残留的节日副本幽灵 CD 缓存，杜绝跨角色污染。
2. **物品栏位扩展与 +N 展开收纳**:
   - 针对角色装备栏（主副手武器、戒指、饰品、套装、项链披风）支持全量采集与图标渲染；
   - 当升级材料/徽章过多时，采用 `+N` 悬停动态展开浮层收纳，彻底解决橙武等核心标识被遮挡的问题。
3. **专属斜杠命令注入**:
   - 注册 `/bgcd`、`/bgrole`、`/bgzl`、`/bgliter` 独立别名，规避其他插件（如 Baganator）抢占 `/bgr` 的冲突。
4. **轻量声望工具类 (Reputation.lua) 性能规范**:
   - 角色登录后静默等待 30 秒初次扫描；战斗状态完全避让；收到 `UPDATE_FACTION` 触发 10 秒长防抖合并；对齐原版数据格式只读安全输出。

### 3.4 历史账单与交易记录 (History / TradeHistory / TradeFix)
1. **双浮窗协同规范**:
   - 接入装备历史价格走势图 Hook 时，必须完整补充原生 `GameTooltip` 绘制链路（`SetOwner`、`SetHyperlink`、底色高亮），确保鼠标处弹出原生装备属性浮窗、右下角弹出渐变价格走势图，严禁覆盖冲掉原生 Tooltip。
2. **交易记录自启动与解耦**:
   - 上游 BGLite 在精简时隐藏了交易 Tab 并注销了 `BG.Init` 队列；BGLite_Plus 改用 `PLAYER_LOGIN` 自愈执行，并在 `Init.lua` 中重建 Tab 按钮，确保切 Tab 时生命周期正确联动。
3. **TradeFix 交易防漏单安全拦截**:
   - 监听 `TRADE_ACCEPT_UPDATE`、`UI_INFO_MESSAGE`，多事件交叉校验交易状态，避免高频或卡顿情况下漏记交金记录。

### 3.5 团队专精嗅探与 Buff 缺口 (RaidTalents / RaidComp)
1. **统一专精中枢 (RaidTalents)**:
   - 集中提供全图超视距专精嗅探能力，解决大团远距离队友专精未知的问题，服务于排兵布阵、Buff雷达与战术站位三大业务。
2. **全口径花名册采集器**:
   - 解决玩家刚进团或重载时由于系统事件尚未就绪导致“进团显示 0 人”或“全家福空白”的时序竞争问题。
3. **双天赋感应与前置声明规范**:
   - 监听玩家天赋切换并广播更新；关键局部函数（如 `BroadcastMySpec`）必须严格前置声明，杜绝空值调用。

### 3.6 打工人收益看板 (WorkerReport)
1. **真实打本时间校准与合体副本折叠**:
   - 引入 `GetTrueRaidTime` 校准真实进本与击杀时钟；
   - 针对合体副本（NAXX 与双龙）实施智能拆分折叠，卡片按周次汇总展示，支持「出勤车数到净落袋」垂直对齐。
2. **数据治理与周四周报提醒**:
   - 引入 `DeduceTableOwner` 准确推断跨号归属；掉落记录列表默认维持 500 条上限，先进先出；
   - 周四登录自动弹出本周打工收益简报；通报文本发送前严格过滤转义符，杜绝 `Invalid escape code` 报错。

### 3.7 团队减伤监控 (RaidCD)
1. **频道智能降级引擎**:
   - 优先适配随机副本频道（`INSTANCE_CHAT`），在非团队或小队环境下自动安全降级为小队或本地输出，杜绝频道不存在导致的发送失败。
2. **跨模块安全引用**:
   - 弹窗与配置模块跨文件访问全局常量（如 `DEFAULT_MONITORED_CLASSES`）必须具备非空防御，杜绝加载时序导致的 nil 报错。

### 3.8 战术站位图 (RaidTacticalMap / RaidMap)
1. **引擎与数据解耦架构**:
   - 地图渲染引擎（坐标投影、缩放、标记拖拽、连线）与副本战术数据（BOSS 技能时序、初始站位、减伤分配）彻底分层，支持按副本独立插拔配置。
2. **1024x1024 规范贴图与防拉伸**:
   - 底图统一采用 1024x1024 规范贴图与高精度 UV 映射，消除非标准分辨率造成的黑边与拉伸形变。
3. **查阅防误触模式与原生 BOSS 成就头像**:
   - 默认开启只读查阅防误触保护，仅在点击【编辑战术】时放行拖拽；BOSS 图标使用原生高清成就头像，界面杜绝不美观边框与 Emoji 乱码方块。
4. **坦克减伤与治疗保坦协同体系**:
   - 深度集成换坦标记、减伤覆盖链与治疗责任区分配，支持战术板一键团队广播。
5. **底层健壮性与 UTF-8 编码规范**:
   - 框体拖拽显式启用 `SetMovable(true)` 并修正光标相对坐标锚定；
   - 所有文件必须保持无 BOM 的纯正 UTF-8 编码，API 调用严格校验参数类型，杜绝 `SetPoint` 传递非法参数。

## 4. 尚未解决的隐患与持续监控项

1. **掉落极端并发与跨区重试压力**:
   - 在部分 Boss 掉落数十件物品的高并发摸尸体场景下，多阶梯异步对账可能面临短时间高频 `FindItemInBiaoGeTable` 扫描，需持续监控大团掉落时的 CPU 耗时与内存峰值。
2. **战术站位图全团广播与网络限流**:
   - 当团长高频拖拽调整站位并开启实时同步时，需确保全团广播数据包具备严格的合并防抖与流量控制，防止短时间触发魔兽插件通信频道限流封锁。
3. **跨客户端版本法术库与副本 ID 漂移**:
   - 时光服（Titan）与传统 WLK/CTM 的部分法术 ID、地下城地图 ID 存在差异，需持续补齐版本适配映射表。
