请基于现有的 XT-002（拆解者 XT-002）Boss 站位攻略页面进行一次“战术可视化升级”。

目标：
把目前的静态站位图升级为“可阅读 + 可播放 + 可演示机制”的 Boss 攻略战术图。

不要推翻现有视觉风格。
保留目前的 UldTitan / 魔兽世界奥杜尔机械遗迹风格、深色金属 UI、蓝色科技边框、Boss 房间背景、中文标注和现有地图素材。

重点不是增加更多文字，而是让第一次见 XT-002 的玩家可以通过“静态状态 + 点击播放”理解整个战斗站位逻辑。

==================================================
一、整体交互模式
==================================================

在战术地图区域增加一个明显但不喧宾夺主的：

▶ 播放战术演示

按钮。

默认状态：
- 地图静止
- 所有角色处于正常站位
- 不显示大量动画
- 保持当前站位图的清晰度
- 用户可以直接阅读站位

点击播放后：
进入约 15～25 秒的“XT-002 战术演示”。

播放按钮变为：
⏸ 暂停

并提供：
↻ 重播

如果合适，可以增加一个很小的：
● 正常阶段
● 特殊机制
● 心脏阶段

时间轴。

==================================================
二、重新优化当前站位逻辑
==================================================

不要把“左出怪 / 右出怪”设计成固定 Boss 机制。

必须明确表达：

“出怪方向取决于 Boss 的实际站位。”

当前推荐战术：
- XT-002 被坦克拉到场地一侧
- 靠近 Boss 的两侧废料堆不作为主要出怪区域
- 远离 Boss 的废料堆作为机器人主要出现方向
- 图上不要让新人误认为“左边永远出怪”或者“右边永远出怪”

因此地图上建议使用动态标签：

【当前出怪方向】

并通过箭头显示：

废料堆 → 机器人 → 团队处理区域

如果 Boss 改变到另一侧，则“当前出怪方向”也应该能够随之改变。

==================================================
三、默认站位
==================================================

默认状态下明确显示：

① 主坦
② 副坦
③ 坦克治疗
④ 团队治疗 / 近战治疗

远程与治疗不要平均环绕整个 Boss 房间。

改为：
- 远程/治疗形成相对集中的团队区域
- 给黑光、白光玩家留出明确的逃离路线
- 玩家之间保持合理距离
- 不要让站位点看起来像机械地均匀分布在圆形地图上

站位图应该强调“团队集中 + 特殊机制向外处理”。

==================================================
四、黑光机制动画
==================================================

“黑光”对应 Gravity Bomb / 重力炸弹。

静态状态：
在团队区域附近显示一个小型紫黑色机制图标：

【黑光】

播放时：

1. 随机选中一名远程/治疗玩家
2. 该玩家获得紫黑色高亮边框
3. 在玩家头顶显示：

   【黑光】

4. 玩家角色周围出现一个非常轻微的紫色脉冲效果
5. 播放一条从玩家当前位置指向左侧安全区域的移动路径
6. 玩家沿路径移动到团队外侧
7. 在安全区域停留
8. 出现一次明显但克制的“重力爆炸”视觉效果
9. 爆炸结束后玩家回到原本团队区域

动画必须让第一次看到的人理解：

“中了黑光 → 离开团队 → 到指定方向处理 → 再回来”

不要制作真实战斗中的血腥或破坏效果。

==================================================
五、白光机制动画
==================================================

“白光”对应 Searing Light / 灼热之光。

静态状态：

在团队区域右侧显示：

【白光】

使用黄色/金色视觉语言，与黑光明显区分。

播放时：

1. 随机选中一名远程/治疗玩家
2. 玩家获得黄色高亮
3. 头顶显示：

   【白光】

4. 玩家周围出现柔和的黄色光环
5. 显示一条向右侧安全区域的路径
6. 玩家向右侧移动
7. 到达安全区
8. 光环短暂增强
9. 玩家回到团队位置

必须让用户一眼理解：

“白光 → 向右侧处理”

==================================================
六、黑光和白光必须使用完全不同的视觉语言
==================================================

黑光：

紫黑色
暗紫色脉冲
向左移动
标签：

【黑光】
远离团队

白光：

金黄色
柔和光圈
向右移动
标签：

【白光】
远离团队

不要使用纯红色作为主要提示色。

不要让两个机制的动画视觉效果混淆。

==================================================
七、正常团队站位动画
==================================================

播放开始后，不要立刻触发机制。

先播放约 2～3 秒正常状态：

- Boss 正常攻击
- 坦克保持 Boss
- 团队保持集中
- 远程/治疗轻微呼吸动画
- Boss 可以有非常轻微的机械运动
- 可以显示：

【正常站位】

让用户先理解“正常情况下大家在哪里”。

然后才进入特殊机制。

==================================================
八、播放流程建议
==================================================

完整演示建议：

0～3 秒：

【正常站位】

Boss
↓
坦克
↓
治疗
↓
远程团队

保持稳定。

--------------------------------

3～7 秒：

触发【黑光】

某个远程玩家被点名。

玩家：
团队 → 左侧安全区

同时出现：

【黑光】
远离团队

然后完成一次机制。

--------------------------------

7～11 秒：

玩家回到团队。

触发【白光】。

另一名玩家被点名。

玩家：

团队 → 右侧安全区

显示：

【白光】
远离团队

然后返回。

--------------------------------

11～15 秒：

模拟一次 Boss 团队伤害 / 全团需要集中治疗的阶段。

显示：

【全团承伤】

治疗区域轻微高亮。

不要让玩家到处移动。

--------------------------------

15～20 秒：

进入：

【心脏阶段 / 机器人阶段】

Boss 停止正常攻击动画。

地图上的主要出怪废料堆开始高亮。

显示：

【机器人出场方向】

废料堆
↓
机器人
↓
团队处理区域

用 2～3 个机器人图标沿固定路线移动。

强调：

“Boss 站位决定主要出怪方向”

最后显示：

【阶段结束 → 恢复正常站位】

然后动画回到初始状态。

==================================================
九、不要把动画做成游戏视频
==================================================

这是“攻略教学动画”，不是战斗模拟器。

因此：

- 不需要完整复刻 WoW 战斗
- 不需要复杂粒子
- 不需要大量 NPC
- 不需要真实伤害数字
- 不需要镜头晃动
- 不需要满屏特效
- 不需要过多 UI

重点是：

位置
方向
角色移动
机制触发
安全区域
机制名称

这些信息必须比装饰更重要。

==================================================
十、地图视觉层级
==================================================

建议将战术地图分成 4 个视觉层：

Layer 1：
原始 Boss 房间背景

Layer 2：
Boss / 玩家 / 坦克 / 治疗 / 远程站位

Layer 3：
机制区域与移动路径

Layer 4：
动画提示、机制名称、箭头、光圈

动画播放时 Layer 3 和 Layer 4 才增强。

正常状态下 Layer 3 / Layer 4 保持低透明度。

这样可以保证：

静态的时候是一张漂亮的攻略图；
播放的时候才变成动态战术演示。

==================================================
十一、交互细节
==================================================

支持：

▶ 播放
⏸ 暂停
↻ 重播

最好支持点击时间轴跳转。

例如：

正常站位
────────────
黑光
────────────
白光
────────────
团队承伤
────────────
机器人阶段

用户点击“黑光”，直接跳到黑光演示。

如果技术实现允许，可以增加：

“自动播放”
“逐步播放”

逐步播放时，每点击一次：

下一步 →

让用户自己理解每个机制。

==================================================
十二、移动端
==================================================

页面可能运行在小程序 / WebView / 手机浏览器中。

因此：

- 播放按钮必须足够大
- 不依赖 hover
- 点击区域至少适合手指操作
- 动画不能依赖鼠标
- 地图可以缩放
- 但不要让 UI 控件随着地图一起缩放
- 文字始终保持可读
- 手机横屏/窄屏情况下也要保持核心站位关系

==================================================
十三、技术实现原则
==================================================

优先使用：

SVG
CSS animation
JavaScript / React 状态控制

如果当前项目已经使用 SVG 地图：
直接在现有 SVG 上增加角色、箭头、路径、光圈和动画。

不要把整个战术图重新绘制成一张新的 PNG。

关键元素应该是独立 DOM / SVG 元素，以便：

- 修改位置
- 修改颜色
- 修改动画
- 修改机制
- 点击交互
- 后续扩展其他 Boss

动画应该尽量使用 transform / opacity 等 GPU 友好的属性。

避免每一帧重新生成整个地图。

==================================================
十四、最重要的 UX 原则
==================================================

第一次打开页面的人：

不点击播放，
也应该能在 5～10 秒内理解：

1. Boss 在哪里
2. 坦克在哪里
3. 团队在哪里
4. 黑光往哪里跑
5. 白光往哪里跑
6. 机器人从哪里出现

点击“▶ 播放战术演示”之后：

用户应该通过动画理解：

“哦，原来黑光往左跑，白光往右跑，
Boss 的站位还会决定机器人从哪边出来。”

这才是这个组件的核心目标。

不要追求动画复杂度。

追求“第一次见 Boss 的玩家看一遍就明白”。

==================================================
十五、最终视觉目标
==================================================

最终效果应该像：

“魔兽世界副本攻略地图 + 战术白板 + 小型动画演示”

而不是：

“复杂的游戏战斗模拟器”。

保持当前 UldTitan 的视觉风格：

暗色
机械
奥杜尔
蓝色科技 UI
金色中文标题
半透明黑色面板
轻微发光
高信息密度

但整体信息层级必须比当前版本更加清晰。

请直接在现有页面基础上修改，不要创建一个完全独立的新页面。

完成后重点检查：

- 默认静态状态是否一眼能看懂
- 黑光是否明确向左
- 白光是否明确向右
- 两者是否明显区分
- Boss 站位是否明确
- 坦克位置是否明确
- 团队是否过度分散
- 出怪方向是否被正确表达为“由 Boss 站位决定”
- 点击播放是否有完整的教学流程
- 暂停/重播是否正常
- 手机端是否可以操作
